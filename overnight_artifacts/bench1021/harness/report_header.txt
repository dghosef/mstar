### Matched settings (every arm)
- bf16 weights; fp32 recurrent (GDN) state: mstar's default is the checkpoint's `mamba_ssm_dtype` (fp32), vLLM `auto` (same), SGLang `--mamba-ssm-dtype float32`.
- Max model length 32768 (= mstar `max_seq_len`); max running sequences 128 (= mstar `gdn_state.max_slots` 129 − 1 sink): vLLM `--max-num-seqs 128`, SGLang `--max-running-requests 128`.
- Prefix caching off: vLLM `--no-enable-prefix-caching`, SGLang `--disable-radix-cache` (mstar has none on this path).
- CUDA graphs on everywhere. mstar runs with `MSTAR_REQUIRE_ACCELERATOR_GRAPHS=1`, so a dropped capture bucket fails startup rather than running eagerly.
- Greedy (`temperature 0`); thinking off on every arm (flat `enable_thinking: false` for mstar, `chat_template_kwargs` for vLLM/SGLang; both fields sent to every arm).
- No speculative decoding (MTP) on any arm.
- Chunked prefill: mstar's Qwen3.5 path has none (whole-prompt prefill); vLLM/SGLang keep chunked prefill at their tuned budget. Not matchable; recorded.
- mstar: `MSTAR_SHM_ARENA=1`; each tree serves with its own shipped config (`configs/qwen3_5_*.yaml`), its own venv, `python -m mstar.cli.main serve`.
- vLLM `--gpu-memory-utilization 0.9`; SGLang `--mem-fraction-static 0.85`.

### Client (one client and one policy for every arm)
`harness/client.py`: closed loop (asyncio semaphore = concurrency) on OpenAI `/v1/chat/completions`, `stream: true`, `ignore_eos: true`, each request's `max_tokens` fixed by its dataset row, so request i does identical work on every engine; same prompts in the same order on every arm.
- TTFT = first SSE chunk with content; TPOT = (e2e − TTFT)/(output_len − 1); output tok/s = output tokens of completed requests / wall time of the measured loop (warmup excluded).
- A request fails on non-200, transport error, SSE error event, empty output, or (engines that report usage) `completion_tokens != max_tokens`. A cell counts only with failed == 0.
- Cross-checked at one point per model with `vllm bench serve` and `sglang.bench_serving`.

### Workloads
- **sharegpt**: ShareGPT V3 (`anon8231489123/ShareGPT_Vicuna_unfiltered`), sampled as `vllm bench serve --dataset-name sharegpt` does (first human turn → prompt; first reply's token length → forced output length; prompt ≤ 1024 and prompt+output ≤ 2048 tokens; shuffle seed 0). Mean input 108 tokens, mean output 297 (4–1500).
- **random_1024_256**: 1024 random-vocabulary tokens per prompt (distinct per request, seed 0), 256 output tokens.

### Protocol
- c = 1, 2, 4, 8, 16, 32, 64, 128; requests per cell = max(16, 8c).
- Warmup: 5 waves (5c requests) before a server's first cell, 1 wave before each later cell; warmup rows disjoint from measured rows.
- 3 rounds per arm; every round is a fresh server process; arm order rotated per round.
- One server on the whole box during any timed cell (every GPU checked < 2 GB before each start); no builds or downloads run during timed cells.
- Recorded per cell: 1-min load average before/after, mean GPU utilization (nvidia-smi every 0.5 s); per server: startup seconds.
- Table cells: output tok/s mean (min–max) over rounds; TTFT/TPOT p50/p99 pooled over every request of the counted rounds.

### Correctness gate (criteria fixed before the run)
- L3 teacher-forced parity vs HF transformers (bf16, sdpa; oracle in the vLLM venv, no mstar import) on 10 text prompts × 128 greedy tokens with `parity.py` / `gate.py` defaults: mean argmax agreement ≥ 0.95 and ≥ worst peer − 0.02; confident-position (top-2 margin > 1) agreement = 1.0; first-disagreement gap ≤ max(1.0, worst peer gap); served-token rank < 5; no empty completion. Same-code control: mstar-pr in a second server process.
- L5 GSM8K (first 250 test questions, 5-shot chat, greedy, thinking off, real EOS): mstar-pr ≥ min(vLLM, SGLang) − 0.03.

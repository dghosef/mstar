Profile verdict (mstar-pr, Python frontend, MSTAR_PHASE_TIMING=100; cells random 1024/256 c=128 and c=32, sharegpt c=128 and c=1):
- Steady decode at batch ~128: iter_total ~3.7-4.3 ms per step, of which worker.postprocess.event_sync (the only real GPU wait) is ~0.17 ms, so the decode loop is CPU-bound; gpu_thread.exec ~1.6 ms and await_gpu ~1.0-1.4 ms are host work.
- Windows that admit new 1024-token prompts show iter_total p95 ~60-67 ms (gpu_thread.exec p95 ~64 ms): a whole-prompt prefill of many 1024-token requests runs as one step and stalls every decoding row. vLLM and SGLang chunk prefills (8192-token budget) and mix them with decode. Hypothesis, consistent with the phase table: this is where mstar's random_1024_256 gap at c>=16 and its high TTFT p99 at c>=64 come from; the chunked-prefill arm (mstar-pr-cp) tests it directly.
